# Matched warmth pipeline

For a native Apple Silicon virtualenv and MPS commands, see [MAC_SETUP.md](MAC_SETUP.md).

Implementation: `matched.py`; wrapper: `run_matched.sh`. This is separate from the EPITOME pilot. No 300-scenario corpus, real Llama activations, or new behavioral results have been generated by implementing this code.

## What is implemented

- 75 scenarios in each of four categories, with deterministic 45/15/15 train/validation/test splits per category (180/60/60 overall).
- Imported scenario JSONL or locally generated **unvalidated synthetic** scenario candidates.
- Three content-preserving rewrite requests per scenario, with resumable per-response outputs.
- Blinded review export; optional independent local LLM screening; explicit acceptance/rejection of whole triplets. Requested labels remain separate from observed warmth ratings.
- Batched activation collection: separate mean-response, last-response-token, and common-suffix-anchor states in one causal forward pass. Independent vectors for each method/layer.
- Training-only full-space linear directions. No PCA or spline is needed for this first linear experiment; paired-PCA and spline comparisons remain later work.
- Held-out direction consistency, category transfer and leave-category-out transfer, category cosine matrices with bootstrap intervals, ordinal projections, middle-level increment cosine/norm ratio, orthogonal curvature, independent split-half curvature agreement, and label-permutation null comparisons.
- Baseline, positive/negative linear steering, multiple norm-matched random directions, and warmth-prompting control.
- Blinded generation ratings, per-condition scores, and per-scenario monotonicity. Flat scores are not counted as successful control.
- Explicit frozen selection before test steering/test diagnostics. There is no automatic choice of a best layer based on geometry or test scores.

## Commands, run separately

From `/workspace/project` inside the container. Default model is the existing local Llama-3.1-8B-Instruct; CPU and eight threads. All model loading is local-only. Commands below use a new `warmth/runs/matched_v1/` directory.

### 1. Prepare scenarios

For the 20-scenario replacement smoke test, use the included [curated seed set](data/CURATED_SMOKE.md):

```sh
sh warmth/run_matched.sh seed --run warmth/runs/mac_curated_v1 --input warmth/data/curated_smoke_v1.jsonl --per-category 5
```

Pass that same `--run` to all subsequent stages. This assistant-authored set replaces flawed generated base scenarios; it does not replace independent review of their warmth rewrites.

Preferred when curated data are available:

```sh
sh warmth/run_matched.sh seed --input /path/to/scenarios.jsonl
```

Each line must contain nonempty string fields:

```json
{"id":"example_001","group":"source_conversation_001","category":"factual_disagreement","prompt":"I think 7 times 8 is 54. Is that right?","base_answer":"7 times 8 is 56, not 54.","invariants":"Correct the product to 56; do not agree that it is 54.","source":"curated"}
```

Exactly 75 examples are required in each category: `factual_disagreement`, `emotional_support`, `advice`, `ordinary_questions`. IDs must contain only letters, digits, underscore or hyphen. Duplicate normalized prompts and repeated source groups are rejected: import one scenario per source group. Near-duplicate semantics require manual review. Reuse source-conversation IDs when importing existing datasets.

Alternative if no curated file exists: generate 300 **candidate** scenarios locally:

```sh
sh warmth/run_matched.sh seed
```

This is a bootstrap option, not an imported Warm AI training corpus. It uses topic/category instructions to draft prompts, base answers and invariants. Independent review must verify base correctness and eliminate duplicate scenarios. The Warm AI-style rewriting constraints are used in the next stage. Do not treat synthetic base answers as verified facts. For an inexpensive smoke run use `--run warmth/runs/matched_smoke --per-category 5`, and pass that same `--run` to subsequent commands.

Scenario generation caches every candidate and saves raw outputs. Invalid JSON or truncation stops the stage; inspect the saved raw record rather than silently accepting it. Use a new run for changed generation settings. A corrected `scenario_candidates/<id>.json` can be supplied before resuming; include all required fields and keep the same ID/category.

### 2. Generate 900 rewrite drafts

```sh
sh warmth/run_matched.sh draft
```

Defaults to a 512-token generation limit. This is a long CPU job and is deliberately not started automatically. Rerunning resumes completed responses. Changing model, source scenarios, instructions or token cap requires a new run. Inputs and completed drafts are frozen by provenance files.

### 3. Export and independently review

```sh
sh warmth/run_matched.sh review
```

Fill `warmth/runs/matched_v1/review.csv`. Do not use `review_key.json` when rating: it reveals requested levels. CSV fields:

- `warmth_0_4`: 0 neutral, 1 slightly friendly, 2 clearly considerate, 3 strongly caring, 4 exceptionally caring.
- `content_preserved_0_1`: same substantive claims, advice, uncertainty, and boundaries.
- `base_correct_0_1`: base answer/invariants are correct; use 0 if uncertain pending verification.
- `quality_1_5`: 1 unusable through 5 fully coherent, relevant and appropriate.
- `reviewer`, `reviewer_kind` (`human` or `llm`), and `reviewer_model` for LLM reviews; notes for uncertainty/disagreements.

A separate local instruct model can provide preliminary screening instead:

```sh
sh warmth/run_matched.sh judge --judge-model /absolute/path/to/independent-instruct-model
```

No second judge model is bundled or automatically downloaded. It must be compatible with the existing Transformers runner. Same-path generator/judge use is rejected; model identity metadata is self-reported and cannot prove independence. Prefer a different family, calibrate on human-reviewed examples, and audit randomly selected accepted triplets. This stage is LLM screening, not human validation. It fills only rows without a reviewer and preserves already entered ratings. Edit ambiguous ratings with an explicit human reviewer attribution; do not silently call model ratings human judgments. The current schema has one adjudicated review per response, not a multi-rater agreement estimator.

Accept only independently ordered and content-preserving triplets:

```sh
sh warmth/run_matched.sh validate
```

Requirements: strictly increasing observed warmth, preserved content, correct base answer, quality >=4, and no truncated drafts. Ties reject a triplet; no labels are invented to force an ordering. `validation_report.json` records rejected IDs/reasons and human-review coverage; `accepted.json` preserves all original splits. Filtering can reduce category/split counts. Do not repeatedly rewrite until one judge approves; record curation and test transfer on a separate unselected set. Changed draft text requires re-export and new ratings.

### 4. Collect all extraction methods

```sh
sh warmth/run_matched.sh collect --batch-size 2
```

Try `--batch-size 4` if memory permits. Both are resumable with the same cache. Mean, last and anchor values are stored separately; batching does not change cache identity. Defaults: layers 12/16/20 (one-based decoder blocks), 1,536 total tokens including suffix, BF16.

The suffix is `\n\n[End of response]`, encoded once as ordinary tokens, appended inside the assistant turn with no EOT, and read at its last token. Separate token encoding deliberately fixes the suffix boundary and token IDs; it may differ from jointly tokenizing the concatenated text. The manifest records that choice and all suffix IDs. Causal attention ensures earlier response states cannot see suffix tokens. A shared suffix does not eliminate context, response-length or position differences. It is never appended during steering generation.

If any sequence is too long, the stage fails before new extraction rather than dropping one warmth level. Raise `--max-length` consistently in collect/analyze/check/steer, which selects a new cache. A different suffix also requires consistent arguments and fresh collection. The model signature includes path, config/tokenizer hashes, and weight sizes/mtimes; it is not a cryptographic weight hash. Never overwrite model files in place while a run is active. One writer per run.

### 5. Analyze validation only

```sh
sh warmth/run_matched.sh analyze --split validation --bootstrap 200
```

Outputs `diagnostics_validation.json` and `vectors.pt`. Each vector is the training mean of within-scenario warm-minus-neutral differences; methods and layers never mix. Empirical cosine quantiles describe dispersion, while bootstrap quantiles describe uncertainty. Zero-norm cosines are reported as null, not fabricated zeros. The independent orthogonal-direction check uses disjoint random training halves, not two overlapping bootstrap samples. Nonzero magnitude is not proof of curvature, and three ordinal labels do not establish equal spacing.

### 6. Run real-model sanity checks

```sh
sh warmth/run_matched.sh check --method last --layer 16
```

Checks batching agreement, zero-hook generation equivalence, baseline equivalence after a nonzero intervention, and hook cleanup. Uses short 12-token generations and writes `sanity_checks.json`. It is not a full causal validation. Unit tests additionally check causal extraction and suffix sensitivity on a tiny randomly initialized Llama; these are not empirical warmth results.

### 7. Compare extraction methods during validation

```sh
sh warmth/run_matched.sh steer --split validation --method last --layer 16 --questions 8 --max-tokens 256
```

```sh
sh warmth/run_matched.sh steer --split validation --method anchor --layer 16 --questions 8 --max-tokens 256
```

Default strengths are -0.5, -0.25, +0.25, +0.5, using one full neutral-to-warm vector as unit strength. There are two random directions plus baseline and a warmth-prompting control: 14 conditions per prompt. Prompt selection round-robins categories. Positive strengths are relative offsets, not guaranteed absolute warmth levels. Current intervention is decode-only; first token is unsteered. All conditions use the same greedy decoding and cap.

Each settings combination creates a separate `generations_<hash>/` folder; outputs and blinded ratings are saved after each response. Resume the same command after interruption. Expand `--questions` to cover all available validation scenarios after smoke testing. Do not launch concurrent writers to the same output folder.

Fill its `ratings.csv` independently, then:

```sh
sh warmth/run_matched.sh score --ratings warmth/runs/matched_v1/generations_HASH/ratings.csv
```

Replace `generations_HASH` with the folder printed by steering. Unlike requested levels, these scores must assess the generated text. Score incorrect claims, false agreement, refusal and quality separately. Current scoring is descriptive; confirmatory paired significance/power analysis and multi-rater agreement remain future evaluation work.

### 8. Freeze the validation-selected settings and evaluate test

The following is an example only: choose method/layer/strengths from validation behavior before freezing.

```sh
sh warmth/run_matched.sh select --method last --layer 16 --max-tokens 256
```

```sh
sh warmth/run_matched.sh steer --split test --method last --layer 16 --questions 60 --max-tokens 256
```

Test steering requires exactly the locked method/layer/strengths/random-control count/token cap. Changing a locked selection requires a new experiment run. Do not delete the lock to retune on test. Filtering may leave fewer than 60 accepted test scenarios; report actual coverage. Independently rate and score this new output folder. Optional final representation diagnostics, after the selection is locked:

```sh
sh warmth/run_matched.sh analyze --split test --bootstrap 200
```
